# Network Topology & IPAM 0.8.6

Install the patch over 0.8.5 and run `php bin/cajeer migrate` (0058). Rebuild Admin UI. Existing source collectors and the manual CMDB topology are unchanged. The release channel remains development pending strict acceptance.

## Collect and inspect

Run `ssh.network`, `winrm.network`, `snmp.interfaces` and `snmp.topology`, `routeros.network`, `proxmox.storage-network`, `vmmanager.network` in the supported modes. Open `/topology` and select a Workspace. The observed topology panel reads the current, revision-fenced snapshots. Only observations at most 15 minutes old are projected. Target/credential changes invalidate snapshots via the existing stores. The original source runs retain history. No remote requests are sent by topology reads or local reconciliation.

The projection has target-scoped stable IDs for devices, interfaces, prefixes and address observations. Derived prefixes are additionally interface-scoped; equal prefixes on different interfaces are not proof of a shared VRF or segment. PVE interfaces are scoped by node or guest; VMmanager networks retain userspace. Linux master links, RouterOS bridge membership and VLAN parent links, PVE guest/bridge and configured parent links are observed configuration. SNMP bridge-port/ifIndex and VLAN evidence comes from the source snapshot; no prefix is invented from an address without prefix length. Only reciprocal LLDP chassis/port pairs that are unique on the current page become physical-link observations. RouterOS neighbors remain unverified observations. MAC/IP/CIDR duplicates and nested prefixes are diagnostics, not evidence of device or network identity. Pagination is by target, default 5, maximum 20; cross-source matching is page-local. Conflict diagnostics are capped at 500 groups with up to 50 example IDs each; counts and a truncation flag are returned. Large pages are rejected explicitly (6 MB); reduce the page size in the UI or API. Snapshots can be partial, particularly PVE and SNMP.

## Reconcile IPAM

First perform ordinary `ssh.inventory`, `winrm.inventory` or `routeros.inventory` Sync to establish an exact CMDB mapping. Collect a fresh complete network snapshot. Select its source in `/topology` and click **Импортировать в IPAM**. Read scopes: inventory.relationships.read, inventory.assets.read, inventory.network.read, connectors.targets.read. Write also requires inventory.network.manage, CSRF, Workspace owner or manager. The server re-reads the snapshot and checks the displayed observed_at and exact mapped asset_id inside the workspace transaction. It uses host identity from the pinned profile or RouterOS device mapping, not hostname/IP. A new audit event records the count of writes.

The importer creates only new networks, NICs with unique MAC, and assigned addresses from explicit NIC/prefix observations. Loopback/link-local/multicast/unspecified and IPv4 network/broadcast addresses and tentative/disabled addresses are not imported. Conflicting CIDR, VLAN, IP, MAC, changed or deleted local rows are reported. Repeated imports of unchanged owned records are idempotent. No automatic deletion, release, reassignment or adoption of manual records. Provenance stores target, observed key and object version. Existing IPAM scopes remain workspace-wide: overlapping or equal CIDRs from distinct targets are not merged automatically. To reuse a known shared network, explicitly enter its IPAM UUID (matching CIDR and known VLAN); its ownership and metadata are not changed. The selection applies to that one network per request. A changed local record is no longer eligible for automatic import. Sources not observed in the latest import remain in place (`retained_unseen`). VMmanager retains its own established network Sync; PVE and SNMP are observation-only for this importer. No VRF schema migration; overlapping userspaces remain separate observations rather than ambiguous local IPAM rows.

GET `/api/v1/inventory/network-discovery?workspace_id=...&limit=5&offset=0` returns source projections, physical links and duplicates. POST `/api/v1/inventory/network-discovery/reconcile` accepts `workspace_id`, `target_id`, `observed_at` and mapped device `asset_id` (exact values from GET) and optional `network_id` (UUID). It never accepts supplied discovery data. Existing `/inventory/topology` continues projecting CMDB relationships and IPAM.

Test: `php tests/network-discovery-smoke.php`, `php scripts/verify-release.php`. PostgreSQL reconciliation tests are included in the RouterOS PostgreSQL TLS fixture test (`python3 tests/routeros-https-integration.py --postgres` with the existing disposable DB environment). Strict acceptance still requires deployed PostgreSQL, real devices, Nuxt and browser E2E.
