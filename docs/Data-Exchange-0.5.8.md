# Data Exchange 0.5.8

## Upgrade

Backup PostgreSQL, stop ingestion/export workers, apply `php bin/cajeer migrate` (0035). No previous migration is altered. Start `php bin/cajeer ingestion:work 20` and `php bin/cajeer data-export:work 10`. Install `deploy/systemd/cajeer-data-export-{worker,retention}.{service,timer}` and enable the timers after adapting `/opt/cajeer` and user. `data-export:retain 100` removes terminal jobs older than seven days. Build Nuxt after updating sources.

## Manual import

Choose an existing active ingestion source of the appropriate kind. Only the grant owner with `ingestion.manage`, `ingestion.write`, the existing inventory/connector read permissions and manager/owner membership may submit. CSRF and session auth required; manual preview/apply limited to 30 requests/minute per actor; a live inspect grant is rechecked at acceptance and processing. Use a dedicated source for manual data if you want separate provenance. Preview requires `format`, `batch_id`, `content` at `POST /api/v1/connectors/targets/{id}/ingestion-sources/{sourceId}/imports/preview`. JSON content is an array of ingestion records or a normalized script result envelope (`schema_version:1`, `schema`, `complete`, `count`, `metric_samples`/`events`/`observations`); CSV is a header with named ingestion fields, comma-separated and RFC4180 quotes. Explicit `observed_at` is required on every row. JSON large numeric values must be decimal strings; CSV values are kept as strings. Optional CSV labels are JSON objects in a quoted cell. Observation `fields` can be JSON or flat supported fields; `tags` and `ip_addresses` can be semicolon-separated. A sample:

```csv
metric,value,kind,observed_at,labels
network.receive_bytes,18446744073709551615,counter,2026-11-12T07:00:00Z,"{""if_index"":""1""}"
```

Use current timestamps within the metric retention window. The preview returns normalized records and a SHA-256 confirmation bound to the source and canonical envelope. It checks schema and duplicate records within the batch; conflicts with already stored data are checked by the worker. Submit the same body plus `confirmation` to `POST .../imports`. Response 202 is queued, not committed. The source/batch identity and payload digest deduplicate retries; changed contents under the same ID conflict. The result is visible in ingestion batch history, including `accepted_by`. Preview never runs code, inserts samples or applies Inventory. Observations remain candidates. For invalid records the 422 problem identifies up to 20 row numbers where possible, or the batch-level problem. CSV syntax errors are file-level. The Scripts UI can download a successful sandbox normalized result for Data Import; it is revalidated as untrusted candidate data. Export archives include provenance metadata and are not implicitly reimportable; map fields explicitly to the input schema, do not import server-generated labels/UUIDs. Existing Inventory Import remains the only manual CMDB application path.

## Export

`POST /api/v1/connectors/targets/{id}/data-exports` with `Idempotency-Key` and JSON `{ "kind":"metrics", "format":"json", "from":"2026-11-12T00:00:00Z", "to":"2026-11-12T01:00:00Z" }`. Optional `series_id` limits metrics to a specific series. UTC half-open range [from,to), maximum 30 days. Kinds: `metrics` (samples), `events` (event observed_at), `observations` (successful candidate batches by received_at), `runs` (completed connector run results by created_at). Formats: JSON archive with schema_version, kind and records; CSV (nested fields as JSON, potentially dangerous spreadsheet formula text escaped with apostrophe); OpenMetrics 1.0 text (latest sample per series in range, generic gauge/counter metric families and original metric/labels/series ID as labels). Numeric metric values are exact decimal strings in JSON and CSV; OpenMetrics consumers may convert to float. Empty results valid. The registered format list is returned with `GET .../data-exports?limit=50&offset=0`; metadata via GET `.../{exportId}`, queued cancellation via POST `.../{exportId}/cancel`. Download GET `.../{exportId}/download` requires the creating actor and live permissions, returns attachment with `X-Artifact-SHA256`. Export requires `inventory.transfer.read`, `inventory.assets.read`, `connectors.targets.read` and workspace membership; event/observation exports also require `ingestion.read`. Worker and download recheck rights. No credentials or keys included. Do not share the downloaded file with unauthorized parties.

The worker holds a workspace transaction lock, SKIP LOCKED claim, bounded SQL timeout, savepoint for known transient errors, retries 30/60/120/240 s (five attempts), and atomic artifact/status commit. Crash before commit leaves queued. No outbound HTTP during transaction. Max 100 jobs/10 pending per workspace, 64 MiB artifact quota, 4 MiB/file, 10,000 records (100 runs); excess fails with `export_limit`, narrow range. No truncation. PostgreSQL text artifact is deliberately bounded to ensure atomicity and avoid orphan objects; not unlimited S3 export. Data is selected at worker execution time, not enqueue time. Retention removes export artifacts and idempotency records after seven days.

## Signed outbound delivery (operator CLI)

Configure `DATA_EXPORT_WEBHOOK_URL` (explicit HTTPS path, no query/redirect/userinfo), `DATA_EXPORT_WEBHOOK_NETWORKS` (required allowlist), optional `DATA_EXPORT_WEBHOOK_CA_FILE`; inject `DATA_EXPORT_WEBHOOK_SECRET` of at least 32 bytes in the protected process environment. `php bin/cajeer data-export:deliver <actor> <target> <export>` reads an already authorized completed artifact and sends exact bytes through pinned TLS transport. The receiver must verify timestamp ±300 s and `X-Cajeer-Signature` = `sha256=` + HMAC-SHA256(secret, `v1.<timestamp>.<Idempotency-Key>\n<Content-Type>\n<raw body>`). Verify `X-Artifact-SHA256`; atomically deduplicate `Idempotency-Key` and store accepted digest before returning 2xx. A repeated key with different digest must reject. Stable key derived from export ID, destination and digest. Temporary transport/429/5xx errors retry up to three total attempts; 3xx, trust and auth failures do not retry. CLI retries across restarts retain same ID. No arbitrary destination from API, no automatic destination subscriptions or persistent delivery ledger in this release. Only use receivers implementing idempotency; HTTP 2xx proves acknowledgement, not downstream processing.

## Data SDK

TypeScript `previewImport`, `applyImport`, `dataExports`, `createDataExport`, `dataExport`, `cancelDataExport`, `downloadDataExport` use existing session/CSRF. Download returns Blob and checksum after verifying SHA-256 with Web Crypto. PHP `Cajeer\ServersSdk\Exporter` extends production exporter interface; implement name/supports/encode; operator sets `DATA_EXPORTER_EXTENSION_FILE` to a trusted absolute PHP entry returning factory `(int $sdkVersion): ExporterInterface`. The built-in registry refuses duplicate names and unavailable formats; custom extension may accept authorized rows and emit bounded UTF-8 text. Example `examples/extensions/data-exporter/entry.php` is real NDJSON output. `MetricConnector` extends connector and metric driver contracts. Trusted code, not sandbox. No arbitrary PHP loading from request. JSON/CSV import uses existing parser/normalizer; new parser extensions not loaded from API.
