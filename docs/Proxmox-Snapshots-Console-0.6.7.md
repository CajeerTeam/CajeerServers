# 0.6.7 — Snapshots & Console Access

## Установка и права

Обновите 0.6.6, `php bin/cajeer migrate` (0043), пересоберите Admin UI и перезапустите workers. Для изменяющих операций нужен включённый существующий флаг remote actions, проверенный TLS-профиль PVE 8/9, синхронизированная VM/LXC без конфликта, MFA и одноразовое Vault-разрешение. Права Cajeer: connectors.actions.read/execute, connectors.targets.read, connectors.credentials.manage, vault.credentials.use, inventory.assets.read. Дополнительно connectors.snapshots.execute для изменения снимков и connectors.console.open для ссылки на консоль; миграция выдаёт их только administrator, остальные роли назначаются явно. PVE: VM.Audit на госте, VM.Snapshot для создания/удаления, VM.Snapshot.Rollback или VM.Snapshot (в зависимости от версии PVE) для rollback. Токен также должен иметь права для существующей проверки узлов и кластера. Выдавайте минимальные права. Для нативной консоли пользователь входит в PVE самостоятельно и должен иметь VM.Console.

## Работа

В разделе коннектора «Удалённые действия» выберите синхронизированную VM/LXC. Введите MFA и нажмите «Загрузить снимки»: запрос к PVE читает актуальное дерево с именами, родителями, временем, описанием, состоянием и ревизией. `current` — псевдозапись, `vzdump` и `pending` — зарезервированные имена. Для создания выберите `vm.snapshot.create` или `lxc.snapshot.create` и задайте имя. Для удаления/rollback выберите соответствующее действие и существующий снимок из списка. Введите точное подтверждение, например `vm.snapshot.delete qemu:101 before_update`, повторно авторизуйте Vault. Результат `submitted` означает только принятый UPID; обновите результат вручную или через план `proxmox.tasks`. Перезагрузите список после завершения.

Rollback уничтожает последующие изменения дисков/конфигурации. Требуется остановленный гость; сохранённое RAM-state QEMU запрещено, чтобы не запустить VM неявно. Снимки создаются без RAM, без force/skiplock/start. Поддержку snapshot конкретным storage и дискам определяет PVE. Ошибка PVE не превращается в успех. Снимки не заменяют backups. HA-managed, заблокированные, шаблонные и неоднозначные гости не изменяются.

Нажмите «Получить ссылку на консоль» после MFA, затем откройте ссылку в новой вкладке. URL генерируется только из текущего проверенного primary host/port и живого узла/VMID: QEMU `console=kvm&novnc=1`, LXC `console=lxc&xtermjs=1`. Нет vncproxy, tickets, встроенного iframe или SSO; браузеру требуется сетевой доступ к PVE, собственная доверенная TLS-цепочка и отдельная авторизация PVE. Запись аудита фиксирует выдачу ссылки, не факт входа в консоль.

## Гарантии и пределы

Один и тот же durable dispatcher блокирует нерешённые power/snapshot действия на гостя, сравнивает digest и дерево снимков перед отправкой, проверяет UPID type/node/VMID, не повторяет изменяющий запрос при потере ответа. Удаление использует DELETE, создание и rollback POST. Ключ идемпотентности привязан также к имени и ревизии снимка. Миграция сохраняет старые строки. Read-only доступ не зависит от флага remote writes, но требует тех же MFA/Vault и permissions для авторизованного доступа к гостю.

Ревизия — хеш видимых метаданных, не уникальный generation ID PVE. Между последним GET и записью остаётся окно внешней гонки. Не используйте параллельное ручное управление тем же гостем. История действий остаётся в connector_actions, список снимков читается живьём, без фонового хранения копии дерева. При неизвестном результате оператор проверяет PVE и подтверждает сверку, а не повторяет команду.
