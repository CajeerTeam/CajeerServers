# Network Configuration Backup 0.8.8

## Возможности

Рабочий коллектор `routeros.configuration-backup` собирает нативный текстовый compact export RouterOS 7 через HTTPS REST. Это не реконструкция из Inventory. Настройки маршрутизатора не изменяются, но на время сбора создаётся уникальный временный файл `cajeer-backup-<32 hex>.rsc`. После чтения по 32768 байт файл удаляется. При ошибке сбор не фиксирует новую версию. При обрыве связи во время удаления возможен оставшийся файл: оператор должен проверить каталог файлов маршрутизатора и удалить только соответствующие временные файлы после остановки текущих сборов. Сервис не выполняет произвольные команды и не восстанавливает конфигурацию автоматически.

Для RouterOS необходимы включённый `www-ssl`, проверенный TLS SHA-256 pin, проверка identity и Vault credential `routeros_api`. Нужны политики `read,write,ftp,test,api,rest-api` для документированных операций создания/чтения/удаления файла; используйте отдельную ограниченную учётную запись, ограничение source IP и management VPN. `show-sensitive` не используется; не выдавайте `sensitive`. Официальное описание: https://manual.mikrotik.com/docs/developer-guides/rest-api/ (Save the configuration to a server). Учитывайте, что RouterOS не экспортирует пользовательские пароли, сертификаты, SSH-ключи и некоторые подсистемы; это не бинарный disaster-recovery backup. SNMP не поддерживает универсальный нативный экспорт; другие провайдеры в эту версию не включены.

## Установка и эксплуатация

1. Наложить ZIP на исходники 0.8.7, сохранив пути. Сделать обычный backup PostgreSQL/Vault перед миграцией.
2. Применить миграции штатным `php bin/cajeer migrate` (см. `php bin/cajeer help`), включая `0060_network_configuration_backup.sql`. Настроить Vault как в 0.8.7, обновить Admin build и перезапустить API/connector worker.
3. В Admin → Сбор данных → выбрать RouterOS target → Коллекторы → Резервные копии конфигурации. Создать план с `routeros.configuration-backup`, `inspect`, сроком действия grant и интервалом/cron. Подтвердить одноразовую MFA-авторизацию Vault. В планах доступен ручной запуск; планировщик и connector worker должны быть запущены. Просмотр истории требует `network.configuration.read`, сбор — `network.configuration.backup` плюс стандартные права connector/Vault/Inventory и роль owner/manager Workspace. Оба новых права выдаются administrator миграцией.
4. После успешного запуска обновить список, выбрать две версии и сравнить либо скачать оригинал `.rsc`. Браузер проверяет SHA-256 перед сохранением. Сравнение игнорирует только сгенерированную дату в первом заголовке и нормализует CRLF; порядок команд и комментарии сохраняются. При крупном diff возвращается ограниченный блок замены (`exact=false`).

## Хранение и безопасность

Каждая изменившаяся конфигурация создаёт новую последовательную версию. Сохраняются исходные байты, SHA-256, размер, версия target и credential, identity hash и дата наблюдения. Повтор идентичной конфигурации при тех же target/credential revisions не создаёт копию; факт успешной проверки доступен в истории запусков. Максимум 1 MiB и 20000 переводов строк; частичный/пустой/повреждённый экспорт не сохраняется. Содержимое шифруется Vault AEAD с индивидуальным DEK и AAD на ID версии и workspace; ротация ключа включает backups. История и commit результата очереди атомарны, повторная проверка прав и ревизий защищает от отозванных грантов. Данные конфигураций не пишутся в обычные run results, аудит и логи. Экспорт и сравнение аудируются. HTTP-запросы требуют сессию и проверку принадлежности Workspace/target; ответы не кэшируются. Скачанные файлы могут содержать IP, правила доступа, комментарии и скрипты — храните их как чувствительные данные.

История сохраняется до удаления target (каскад) или штатной очистки БД оператором; автоматическое удаление версий не включено. Не забывайте включать PostgreSQL и Vault key в защищённые системные резервные копии. Никакого автоматического восстановления на устройство нет.

## Проверки

`php tests/network-configuration-backup-smoke.php` — валидация, dedup-нормализация, diff и криптография. `python3 tests/routeros-https-integration.py` — настоящий TLS, фиксированные REST запросы, chunking, ошибки и очистка. `python3 tests/routeros-https-integration.py --postgres` — дополнительно disposable PostgreSQL 17+, миграция, Vault, Queue, версии, diff и export (см. CAJEER_PG_TEST в тесте). Live acceptance на физическом RouterOS требуется до production promotion.
