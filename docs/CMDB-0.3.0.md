# CajeerServers 0.3.0 — Inventory / CMDB Stable Integration

## Назначение

CajeerServers остаётся **веб-ресурсом**, не ОС и не агентом. Релиз 0.3.0 связывает существующие Inventory CRUD, IPAM, отношения, каталог, provenance и импорт/экспорт с проверкой целостности всей CMDB. Никаких скриптов на управляемых хостах новая диагностика не выполняет.

## Реализовано

- `core/Inventory/CmdbIntegrity.php`: SQL-проверки согласованности данных на одном read-only snapshot PostgreSQL (`REPEATABLE READ`, `statement_timeout=5s`, rollback вместо commit). SQL выполняется исключительно на сервере БД, наружу возвращаются агрегированные числа. Проверка не изменяет существующие данные и не пытается их «чинить» без оператора.
- `php bin/cajeer inventory:integrity [--json] [--deep]`: реальная команда контроля целостности; exit code `0` только при отсутствии нарушений, `1` при ошибке, `2` при некорректных опциях. `--deep` дополнительно ищет циклы с recursive CTE/CYCLE. Для больших графов может сработать таймаут: это ошибка проверки, не успешный результат.
- `GET /api/v1/admin/cmdb-integrity`: защищённый сессионным RBAC (`admin.dashboard.read`) endpoint. Ответ `200` после успешного чтения, а нарушения передаются через `ok=false`; ошибки соединения обрабатывает общий HTTP kernel. Внешний анонимный доступ закрыт.
- Главная страница Nuxt отображает реальные числа assets, IPAM, relationships, импортов и результат каждой проверки.
- Импорт: `TransferService::dispatch()` сначала коммитит стабильный UUID queue-job в PostgreSQL и лишь затем отправляет задание в выбранную очередь. Повторный dispatch использует тот же UUID; ошибка очереди оставляет пакет для безопасного повтора. Успешный запрос не публикует непроверенные shell/PHP-задачи.

## Что проверяется

| Область | Проверка |
|---|---|
| Workspaces | Каждый workspace имеет активного owner |
| Assets | Владелец состоит в workspace и активен |
| IPAM | Подсети не пересекаются, IP принадлежит CIDR |
| Interfaces | Интерфейсы принадлежат активным ресурсам |
| IP Assignments | IP не назначен удалённому/чужому интерфейсу |
| Topology | Нет связей с удалёнными объектами или чужим workspace |
| Structural relations | У ресурса нет нескольких структурных родителей |
| Tags | Реляционные теги совпадают с JSONB tags объекта |
| Groups | Группы и объекты не имеют нарушенных workspace-связей (soft-delete сохраняет состав группы для восстановления) |
| History | Версия последней ревизии совпадает с текущей версией объекта |
| Provenance | Все поля наблюдения имеют запись происхождения |
| Imports | Прогресс совпадает с сохранёнными результатами обработки |
| Credential Bindings | Привязки не нарушают workspace; soft-delete может сохранить ссылку без раскрытия секрета |
| Deep (опционально) | Отсутствуют циклы в направленных связях |

SQL-запросы не принимают пользовательских имён таблиц или полей и не возвращают исходные записи. **Возможные ошибки БД/таймауты должны исправляться администратором**, не автоматически.

## Развёртывание поверх 0.2.9

1. Сделать резервную копию PostgreSQL и файлов конфигурации. Распаковать патч 0.3.0 поверх 0.2.9, сохраняя относительные пути.
2. Проверить `php bin/cajeer version` (должна быть `0.3.0`), затем `php bin/cajeer inventory:preflight --strict --json`.
3. Выполнить `php bin/cajeer migrate` и `php bin/cajeer migrate:validate`, затем `php bin/cajeer inventory:integrity --json`; при необходимости — `--deep`. Данные исправляются штатными API и миграциями, не прямым удалением исторических таблиц.
4. Запустить `php tests/cmdb-integrity-smoke.php`, `php tests/import-dispatch-smoke.php` и `php scripts/verify-release.php` (включая сканер миграции 0016).
5. На изолированной инфраструктуре с настоящими PostgreSQL 17/18, Redis, Composer/npm dependencies и Nuxt запустить integration и browser E2E; выполнить `php scripts/verify-release.php --strict` и `php bin/cajeer release:check --strict --json`.

Добавлена миграция `0016_cmdb_stability.sql`: backfill provenance для созданных вручную assets, trigger записи происхождения новых ручных изменений и SQL-защита от удаления asset с активными IPAM interfaces. Старые UUID не переписываются. Сначала сделайте резервную копию PostgreSQL.

## Эксплуатационные ограничения

- CMDB-скан в строгом release gate требует подключённой PostgreSQL и полной миграции до 0016; без БД выдаётся ошибка, а не ложный успех.
- `composer.lock` и `admin/package-lock.json` должны быть созданы настоящими менеджерами зависимостей и закоммичены. Без этих файлов строгий production-gate остаётся закрытым.
- Нельзя объявлять 0.3.0 production-validated, пока не пройдены настоящие PostgreSQL/Redis интеграции, `npm run build` и browser E2E.
- Proxmox, VMmanager, SSH/WinRM, агенты, исполнение удалённых команд и полноценный Vault **не входят** в 0.3.0. Они относятся к следующим версиям.
